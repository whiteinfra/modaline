## 1. Вступ

«ModaLine» — веб-застосунок інтернет-магазину одягу для малого бізнесу (до 20 співробітників). Покупці переглядають каталог, підбирають розмір і колір, оформлюють та оплачують замовлення онлайн. Менеджер і адміністратор у тому ж застосунку ведуть асортимент, залишки та статуси замовлень.

## 2. Мета і задачі

- **Мета:** продавати онлайн цілодобово і скоротити час від оформлення замовлення до передачі на склад з 1 доби до 2 годин.
- **Основні задачі:**
  - каталог товарів з пошуком і фільтрами (категорія, розмір, колір, ціна);
  - реєстрація й авторизація покупців, особистий кабінет з історією замовлень;
  - кошик і оформлення замовлення з вибором доставки (Нова пошта, самовивіз);
  - онлайн-оплата карткою (платіжний шлюз, тестовий режим до релізу) та оплата при отриманні;
  - адмін-панель для товарів, залишків і статусів замовлень;
  - email-повідомлення про зміну статусу замовлення.

## 3. Цільова аудиторія

| Роль | Хто це | Ключові сценарії |
|---|---|---|
| Гість | Відвідувач без облікового запису | Перегляд каталогу, пошук, фільтри, картка товару, додавання в кошик |
| Покупець | Зареєстрований клієнт 16–45 років, переважно зі смартфона | Реєстрація/вхід, оформлення й оплата замовлення, історія замовлень, повернення |
| Менеджер | Співробітник відділу продажів | Обробка нових замовлень, зміна статусів, зв’язок з клієнтом |
| Адміністратор | Власник або відповідальний за сайт | Керування товарами, цінами, залишками, користувачами та ролями |

## 4. Функціональні вимоги

| ID | Функція | Опис | Критерії приймання |
|---|---|---|---|
| FR-01 | Каталог товарів | Список товарів з пагінацією (24 на сторінку), сортуванням за ціною та новизною | Відображаються лише активні товари з залишком > 0; сортування змінює порядок без перезавантаження сторінки |
| FR-02 | Пошук і фільтри | Пошук за назвою/артикулом, фільтри: категорія, розмір, колір, діапазон цін | Комбінація фільтрів повертає коректну вибірку; порожній результат показує повідомлення «Нічого не знайдено» |
| FR-03 | Картка товару | Фото, опис, склад тканини, таблиця розмірів, вибір розміру й кольору | Кнопка «У кошик» неактивна, доки не обрано розмір |
| FR-04 | Реєстрація та вхід | Реєстрація за email і паролем, вхід, вихід, відновлення пароля | Email унікальний; пароль ≥ 8 символів; після 5 невдалих спроб вхід блокується на 15 хв |
| FR-05 | Кошик | Додавання, зміна кількості, видалення позицій, підсумкова сума | Сума перераховується миттєво; кошик гостя зберігається 7 днів (cookie) і переноситься після входу |
| FR-06 | Оформлення замовлення | Контактні дані, спосіб доставки, спосіб оплати, коментар | Замовлення отримує номер і статус «Нове»; покупець отримує email-підтвердження |
| FR-07 | Онлайн-оплата | Оплата карткою через платіжний шлюз | Після успішної оплати статус змінюється на «Оплачено»; при помилці замовлення лишається «Очікує оплати» |
| FR-08 | Адмін-панель: товари | CRUD товарів, завантаження фото, керування залишками за розмірами | Зміни видно в каталозі ≤ 1 хв; видалення — «м’яке» (архівація) |
| FR-09 | Адмін-панель: замовлення | Список замовлень з фільтром за статусом/датою, зміна статусу | Кожна зміна статусу пишеться в журнал (хто, коли, з якого в який) |
| FR-10 | Повідомлення | Email при створенні, оплаті, відправленні замовлення | Лист надсилається ≤ 2 хв після події; є посилання на сторінку замовлення |

## 5. Нефункціональні вимоги

- **Продуктивність:** відповідь API ≤ 300 мс для 95 % запитів; відображення каталогу (LCP) ≤ 2,5 с у мережі 4G; не менше 200 одночасних користувачів.
- **Безпека:** авторизація за OAuth2 (password flow) з JWT (access-токен 15 хв, refresh-токен 7 днів); паролі зберігаються як bcrypt-хеш; лише HTTPS (TLS 1.2+); захист від SQL-ін’єкцій, XSS і CSRF; розмежування ролей (RBAC).
- **Сумісність:** Chrome, Firefox, Edge, Safari (дві останні версії); адаптивна верстка 360–1920 px; Windows 10/11, macOS, Android 10+, iOS 15+.
- **Надійність:** доступність ≥ 99,5 % на місяць; щоденне резервне копіювання БД (RPO ≤ 24 год, RTO ≤ 4 год).
- **Логування/моніторинг:** структуровані JSON-логи з request-id, метрики Prometheus, дашборд Grafana, сповіщення, якщо частка відповідей 5xx перевищує 1 % за 5 хв.
- **Зручність:** оформлення замовлення не більше ніж за 3 кроки; інтерфейс українською мовою (англійська — у наступних версіях).
- **Відповідність:** обробка персональних даних згідно із Законом України «Про захист персональних даних» та GDPR.

## 6. Обмеження та припущення

- Технології: Python 3.12 + Flask (REST API), React 18 + Vite (клієнт), PostgreSQL 16, Docker.
- Строки: MVP за 6 тижнів (3 спринти по 2 тижні); команда 1–2 розробники.
- Бюджет інфраструктури — до 20 $/міс (один VPS + об’єктне сховище для фото).
- До релізу платіжний шлюз працює лише в тестовому режимі.
- Припущення: асортимент до 2 000 SKU, до 500 замовлень на добу; доставка лише по Україні.

## 7. Інтерфейс користувача (коротко)

Основний мікро-флоу покупця:

`Головна → Каталог (фільтри) → Картка товару → Кошик → Оформлення (контакти → доставка → оплата) → Підтвердження`

Мікро-флоу адміністратора: `Вхід → Дашборд → Товари / Замовлення → Картка замовлення → Зміна статусу`.

Перелік сторінок MVP: головна, каталог, картка товару, кошик, оформлення замовлення, вхід/реєстрація, особистий кабінет, адмін: товари, адмін: замовлення.

## 8. Архітектурні рішення (високорівневі)

- **Архітектура:** клієнт-сервер; SPA (React) ↔ REST API (JSON over HTTPS) ↔ PostgreSQL; фото товарів — в S3-сумісному сховищі.
- **Сервер:** Flask-застосунок (модулі `catalog`, `auth`, `cart`, `orders`, `admin`), gunicorn за nginx (reverse proxy, TLS).
- **БД:** PostgreSQL 16, міграції через Alembic, щоденний `pg_dump` у сховище бекапів.
- **CI/CD:** GitHub Actions — lint і тести на кожен push/PR; на тег `v*` збирається реліз-артефакт і Docker-образ.
- **Деплой:** `docker compose` на VPS; середовища `dev` (локально), `staging`, `production`.

## 10. Критерії приймання

Реліз приймається, якщо: усі функціональні вимоги FR-01…FR-10 реалізовані; модульні та інтеграційні тести проходять у CI; критичних і блокуючих дефектів немає; оновлено `CHANGELOG.md` і release notes; виконано [ACCEPTANCE_CHECKLIST.md](ACCEPTANCE_CHECKLIST.md).

| ID | Тест-кейс | Очікуваний результат |
|---|---|---|
| TC-01 | Відкрити каталог, обрати фільтр «Розмір M» | Показано лише товари з наявним розміром M |
| TC-02 | Зареєструватися з уже існуючим email | Повідомлення «Користувач з таким email вже існує», обліковий запис не створено |
| TC-03 | Увійти з правильними даними | Отримано JWT, показано ім’я користувача в шапці |
| TC-04 | Додати 2 товари в кошик і змінити кількість | Сума кошика перерахована правильно |
| TC-05 | Оформити замовлення з оплатою карткою (тестова картка) | Статус «Оплачено», надіслано email-підтвердження |
| TC-06 | Менеджер змінює статус замовлення на «Відправлено» | Статус змінено, запис з’явився в журналі, клієнт отримав лист |
